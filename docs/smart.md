# Smart truck functions (2020s) and their feasibility as ETS2 1.60 plugin modules

Scope: ETS2 1.60 single player, native plugin with: SDK telemetry, GPS route (nodes + heights), AI traffic list (pos/speed/accel), traffic lights, throttle/brake override, steering angle override, shift-decision hook, cvar changes.

Confidence key: [V] opened page; [S] search snippet only; [E] from the exe strings / project notes; [I] inference.

## 0. What ETS2 1.60 already has (exe strings, [E])

Cvars (settings) found in `eurotrucks2.exe`: `g_acc` (ACC gap, meters; in-game 20/30/40 m), `g_cruise_control_grid` (step size), `g_cruise_control_smart`, `g_emergency_brake`, `g_emergency_brake_mode`, `g_lane_assistant` (LDW / LKS, only >55 km/h), `g_motor_brake_auto`, `g_retarder_auto` ("Automatic retarder %s"), `g_automatic_headlights`, `g_auto_traffic_headlights`, `g_speed_warning`, `g_hud_speed_limit`, `g_use_speed_limiter`, `g_adaptive_shift`. Option labels: `@@adaptive_cruise_control@@`, `@@smart_cruise_control@@`, `@@emergency_brake@@`, `@@auto_motor_brake@@`, `@@auto_retarder@@`, `@@automatic_headlights@@`, `@@adviser_speed_limit@@`.
Inputs: `o_im_cruise_ctrl`, `_inc`, `_dec`, **`o_im_cruise_ctrl_resume`** (a stock resume key exists), `o_im_auto_engine_brake`, `o_im_auto_retarder`, `accmode`, `laneassist`, `laneassmode`.
Not present: any `cruise*min*speed` cvar -> the minimum cruise speed is a hard-coded constant. No auto-wiper string (interior wiper strings are about animation only). So: auto headlights, auto engine brake/retarder, AEB, basic LKA, speed-limit adviser and speed limiter already exist in stock; auto wipers do not.

Stock ACC history: hidden experimental in 1.44, official in 1.47 with Emergency Braking System ("keeps distance and speed from the vehicle ahead when the truck is in cruise control mode"; EBS brakes when a collision looks unavoidable). SCS blog: https://blog.scssoft.com/2023/04/euro-truck-simulator-2-147-update.html [S], https://blog.scssoft.com/2023/03/euro-truck-simulator-2-147-open-beta.html [S]; Traxion: https://traxion.gg/american-truck-simulator-and-euro-truck-simulator-2-v1-47-update-drops-featuring-real-world-truck-tech/ [S].

Minimum cruise speed: only a 2013 Steam post gives a number: "Also have to be traveling over 30 mph (like real C/C)" (https://steamcommunity.com/app/227300/discussions/0/864973980814103336 [V]); the figure is commonly quoted as 30 km/h in the community, and the truck-simulator wiki was not reachable (HTTP 402). **Treat the exact number as unverified; measure it in game** (press C at 20, 25, 29, 31 km/h; also check whether ACC following a slow car drops cruise when the truck falls below it). No official SCS statement found.

## 3. ACC Stop&Go in ETS2: what is known and what the module must do

Facts [E]/[S]:
- Stock cruise is speed-gated by a hard-coded constant (no cvar; community: ~30 km/h, 2013 post says 30 mph: unverified). There is a stock resume input (`o_im_cruise_ctrl_resume`), so the game keeps a "last set speed".
- Stock ACC follows a slower lead ("it is adapting on the speed of the traffic ahead", Steam 2024: https://steamcommunity.com/app/227300/discussions/0/4336483638879352695 [S]). Whether it brakes to a standstill, holds, and re-launches is undocumented; player reports only describe EBS braking hard. Expected [I]: when the follow speed drops below the minimum, cruise simply disengages (the usual car-style behavior of a non-Stop&Go ACC).
- ets2la_plugin knows the game_actor fields `cruise_control_enabled` (+0x175) and `cruise_control_speed` (+0x178) for 1.55 (`docs/acc.md`; re-verify for 1.60) and can write throttle/brake inputs.

Tests to run first (probe plugin, one session):
1. Find the minimum: press C at 20/25/29/31 km/h, note the threshold and whether it is km/h or mph-based.
2. Follow a slow AI car with ACC until it stops: does cruise drop out, at what speed, and does the EBS take over?
3. At 10 km/h write `cruise_control_enabled = 1` and `cruise_control_speed = 50` directly: does the per-frame cruise update keep it or clear it? If it keeps it and stock ACC brakes to 0 and re-launches, Stop&Go is almost free (module just arms cruise and re-arms it after a stop).
4. Check whether `g_cruise_control_smart` (the test profile uses 3) changes any of this (option tooltip `smart_cruise_control_op_tooltip`).

Module design if stock cruise refuses low speed (likely):
- State machine: OFF -> ARMED (driver pressed C or resume below v_min, or stock cruise fell out while the lead was slowing) -> FOLLOW (plugin drives throttle/brake) -> HOLD (v = 0, brake held) -> RELAUNCH -> HANDOVER (v >= v_min + 3 km/h: write cruise set speed = remembered target, enabled = 1, release overrides) -> back to ARMED when stock cruise disengages again.
- Lead selection: from the traffic list keep vehicles whose position projected on the own route polyline is ahead (0-120 m), lateral offset < ~1.8 m from the lane center (or own heading line if lane geometry is unknown), heading within 30 deg; nearest wins. Use lead speed and acceleration directly from the list (no estimation noise). Fallback without a lead: hold set speed (classic cruise) or, with traffic lights read, stop at red.
- Gap law: d_target = d0 + t_gap * v with d0 = 4-6 m, t_gap = `g_acc`/v-equivalent (so the same preference as the stock ACC). Controller: a_cmd = k_d (d - d_target) + k_v (v_lead - v) + a_lead feed-forward, clamp to [-3, +1.5] m/s^2; map a_cmd to throttle (positive) or brake (negative) via a simple inverse model (mass from telemetry, engine torque from defs) plus an integrator. At standstill keep brake >= 0.3 until relaunch.
- Relaunch: auto if the lead moves off within 2-3 s (Detroit rule) and the gap exceeds d0 + 2 m; otherwise wait for the driver (throttle tap or the resume key) and show an "ACC: press resume" hint. Driver brake pedal always cancels to OFF; throttle pedal overrides the plugin throttle (max of both).
- Hand-back: above v_min the stock cruise+ACC takes over so the stock EBS stays armed; the plugin keeps monitoring and re-arms when the stock cruise drops.
- Effort: medium-hard; the controller is textbook, the risk is lane assignment of the lead and interaction with the stock EBS (it may brake while the plugin is also braking: fine) and with the stock automatic gearbox at low speed (TrueShift creep/stop logic must agree).

## 4. Top 8 by value for a sim driver versus effort

1. **ACC gap as a function of speed** (set `g_acc`): trivial, visible every drive. Needs only the cvar setter.
2. **Predictive gear selection + eco-roll** (TrueShift v1 with look-ahead): the core product; medium effort, high value (realistic AMT feel on every hill).
3. **Predictive cruise control with over/underspeed band and crest roll** (PPC/I-See behavior): high value for the "real truck" feel; medium, reuses the grade profile and model from 2. Expose under/overrun limits and Eco/Standard/Power levels.
4. **Predictive speed adaptation**: slow down for speed-limit changes, curves and roundabouts using route curvature and the SDK speed limit: high value in ETS2 (lots of country roads and roundabouts), medium effort, same actuator as 3.
5. **ACC Stop&Go / traffic-jam follow**: high value in cities and jams, medium-hard; depends on traffic-list parsing and the handover trick in section 3.
6. **Downhill speed control with overspeed band + predictive release** (Iveco GAP style): low-medium effort on top of stock auto brake toggles; moderate value.
7. **Hill start aid + creep/maneuvering** (from `docs/lowspeed.md`): low-medium effort, moderate value, mostly for wheel/pedal users; belongs in TrueShift.
8. **Lane centering at all speeds (own LKA) / blind-spot and lane-change warning**: LKA is hard (lane line data) but high value and prerequisite for a full traffic-jam assist; the blind-spot warning is an easy by-product of the traffic list. Do the warning first, LKA last.

Not worth building: driver-inactivity stop, auto wipers, driver coaching (unless as a fun side panel).
